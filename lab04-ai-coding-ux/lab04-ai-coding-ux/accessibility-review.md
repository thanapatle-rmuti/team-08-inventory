# Accessibility Review (WCAG 2.1 AA) - Lab 04

## 1. ตารางประเมินผลการตรวจ Accessibility Checklist

| รายการตรวจ | ผ่าน หรือ ไม่ผ่าน | สิ่งที่แก้ / ข้อสังเกตในการออกแบบ |
| :--- | :---: | :--- |
| **1. ข้อความหลักบนพื้นขาว contrast อย่างน้อย 4.5:1** | **ผ่าน** | ใช้สีข้อความเข้ม `#111827` (Very Dark Gray/Black) บนพื้นหลังสีขาว `#FFFFFF` ซึ่งให้ค่า Contrast Ratio อยู่ที่ **16.1:1** สูงกว่าเกณฑ์ขั้นต่ำ 4.5:1 ของ WCAG AA |
| **2. ปุ่มหลักมี contrast เพียงพอ** | **ผ่าน** | ปุ่มหลักใช้สีน้ำเงิน Primary `#1E40AF` พื้นหลัง และตัวอักษรสีขาว `#FFFFFF` ได้ Contrast Ratio อยู่ที่ **8.5:1** (ผ่านเกณฑ์สำหรับ UI Component และ Large/Bold Text) |
| **3. ทุกช่องกรอกมี label ที่มองเห็น** | **ผ่าน** | ทุกช่องอินพุตมี `<label>` แสดงอยู่ด้านบนกล่องข้อความเสมอ ไม่พึ่งพาเพียง Placeholder ที่จะหายไปเมื่อผู้ใช้เริ่มพิมพ์ |
| **4. ช่องที่บังคับกรอกมีสัญลักษณ์ชัด** | **ผ่าน** | ใส่เครื่องหมายดอกจันสีแดงหรือข้อความกำกับ `*` ที่ Label และมีคำอธิบายที่หัวฟอร์มระบุว่า *"ช่องที่มีเครื่องหมาย (*) เป็นช่องที่จำเป็นต้องกรอก"* |
| **5. Error ไม่ได้ใช้สีอย่างเดียว มีไอคอนหรือข้อความด้วย** | **ผ่าน** | ช่องที่มีข้อผิดพลาด นอกจากกรอบสีแดงแล้ว ยังมีไอคอน `(X)` และข้อความอธิบายวิธีแก้กำกับอยู่ใต้ช่องเสมอ (ช่วยให้ผู้มีภาวะตาบอดสีเข้าใจได้ทันที) |
| **6. ลำดับการกด Tab เรียงบนลงล่าง ซ้ายไปขวา** | **ผ่าน** | จัดเรียงโครงสร้าง DOM และ Form Fields ตามลำดับการอ่านธรรมชาติ (Top-to-Bottom, Left-to-Right) โดย Tab Index เริ่มจาก Type -> SKU -> Name -> Qty -> Buttons |
| **7. ปุ่มมีชื่อบอกหน้าที่ ไม่ใช่ OK หรือกากบาท** | **ผ่าน** | ใช้ชื่อปุ่มบอก Action ชัดเจน เช่น `[ บันทึกสินค้า ]`, `[ ยกเลิก/กลับ ]`, `[ + เพิ่มสินค้าใหม่ ]` แทนการใช้คำกำกวมอย่าง "OK", "Submit" หรือเครื่องหมาย "X" |

## 2. บันทึกจุดที่ AI ทำพลาดและได้รับการแก้ไขด้วยตนเอง (อย่างน้อย 2 จุดตาม Rubric)

### จุดที่ 1: การใช้ Placeholder สีเทาอ่อนแทน Visible Label
- **สิ่งที่ AI สร้างมาให้ในดราฟต์แรก:**  
  AI ร่างแบบฟอร์มโดยไม่มีป้ายกำกับ `<label>` เหนือช่องกรอก แต่ใส่คำใบ้ไว้ในช่องเป็น Placeholder จาง ๆ เช่น `[ พิมพ์จำนวนตรงนี้... ]` สี `#9CA3AF` ซึ่งมี Contrast เพียง 2.9:1 (ไม่ผ่านเกณฑ์ WCAG AA 4.5:1) และเมื่อผู้ใช้คลิกพิมพ์ ข้อความใบ้จะหายไปทันที ทำให้ผู้ใช้สูงวัยหรือทักษะเทคโนโลยีต่ำ (อย่างพี่ศรี) ลืมว่ากำลังกรอกข้อมูลอะไร
- **การแก้ไขโดยมนุษย์:**  
  เพิ่ม Label ตัวหนาสี `#111827` ไว้ด้านบนของทุกฟิลด์อย่างถาวร พร้อมย้ายคำแนะนำไปไว้ใต้ช่องเป็น Helper Text ที่อ่านง่ายและไม่หายไปขณะพิมพ์

### จุดที่ 2: ข้อความแจ้งเตือน Error คลุมเครือและใช้เพียงกรอบสีแดง (Missing Meaningful Error & Icon)
- **สิ่งที่ AI สร้างมาให้ในดราฟต์แรก:**  
  เมื่อผู้ใช้กรอกจำนวนสต็อกติดลบ AI กำหนดเพียงเปลี่ยนกรอบช่องเป็นสีแดง และขึ้นข้อความสั้น ๆ ว่า `Invalid input` ซึ่งขัดกับหลัก Accessibility (ผู้ใช้ตาบอดสีจะไม่ทราบว่าเกิดอะไรขึ้น) และขัดกับหลัก Usability เพราะไม่ได้บอกว่าผิดตรงไหนและต้องแก้อย่างไร
- **การแก้ไขโดยมนุษย์:**  
  เพิ่มไอคอน `(X)` ด้านหน้าข้อความ และเปลี่ยนข้อความระบุสาเหตุพร้อมวิธีแก้อย่างเจาะจงเป็นภาษาไทย: `"(X) จำนวนสต็อกต้องเป็นตัวเลข 0 หรือมากกว่า (ไม่สามารถติดลบได้)"` พร้อมมี ARIA alert attribute สำหรับ Screen Reader

### จุดที่ 3 (เพิ่มเติม): การขาด Feedback ยืนยันหลังการบันทึก (Lack of Success State)
- **สิ่งที่ AI สร้างมาให้ในดราฟต์แรก:**  
  เมื่อกดบันทึกสำเร็จ AI เคลียร์ฟอร์มกลับเป็นหน้าว่างเปล่าทันทีโดยไม่มีข้อความใด ๆ ทำให้ผู้ใช้เข้าใจผิดว่าระบบค้างหรือยังไม่ได้บันทึก
- **การแก้ไขโดยมนุษย์:**  
  เพิ่ม **Success Banner State** สีเขียว `#15803D` พร้อมไอคอน `(✓)` ด้านบนสุดของหน้าจอ ระบุรหัสและชื่อสินค้าที่เพิ่งบันทึกสำเร็จอย่างชัดเจน
