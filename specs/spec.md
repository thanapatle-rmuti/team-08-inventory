# Spec: ฟีเจอร์แจ้งเตือนสต็อกต่ำ และรายงานมูลค่าสต็อก

## 1. เป้าหมาย (Goal)
เพิ่มความสามารถให้ระบบ inventory แจ้งเตือนผู้จัดการเมื่อสินค้าใดมีสต็อก
ต่ำกว่า threshold ที่ตั้งไว้รายสินค้า โดยแจ้งผ่าน Email และ SMS (ใน lab ใช้ print แทนการส่งจริง)
และให้ผู้จัดการดูรายงานมูลค่าสต็อกรวมแยกตามหมวดหมู่สินค้าได้

## 2. User Story
| รหัส | User Story |
|------|-----------|
| US-01 | As a พนักงานคลังสินค้า, I want บันทึกการรับ/จ่ายสินค้าพร้อมอัปเดตสต็อกทันที, so that สต็อกในระบบสะท้อนจำนวนจริง |
| US-02 | As a ผู้จัดการ, I want รับการแจ้งเตือนทันทีเมื่อสินค้าใดต่ำกว่า threshold, so that สั่งซื้อได้ก่อนของหมด |
| US-03 | As a ผู้จัดการ, I want ดูมูลค่ารวมของสต็อกแยกตามหมวดหมู่, so that ตัดสินใจด้านการเงินได้ |
| US-04 | As a ผู้จัดการ, I want ตั้งค่า threshold รายสินค้าได้, so that กำหนดจุดสั่งซื้อที่เหมาะสมกับสินค้าแต่ละชนิด |
| US-05 | As a ผู้จัดการ, I want เลือกช่องทางแจ้งเตือน (Email/SMS) ได้, so that รับแจ้งเตือนผ่านช่องทางที่สะดวก |

## 3. Acceptance Criteria (Given-When-Then)

### AC ของ US-01

```gherkin
Scenario: รับสินค้าเข้าคลัง
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 20 เมตร
  When พนักงานบันทึกรับเข้า 30 เมตร
  Then สต็อกคงเหลือ 50 เมตร

Scenario: จ่ายสินค้าออกสำเร็จ
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 20 เมตร
  When พนักงานบันทึกจ่ายออก 10 เมตร
  Then สต็อกคงเหลือ 10 เมตร

Scenario: จ่ายสินค้าออกเกินสต็อก
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 5 เมตร
  When พนักงานบันทึกจ่ายออก 10 เมตร
  Then ระบบปฏิเสธการจ่าย
  And แสดงข้อความ "สต็อกไม่เพียงพอ"

Scenario: บันทึกจำนวนเป็น 0 หรือค่าลบ
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 20 เมตร
  When พนักงานบันทึกรับเข้า 0 เมตร หรือ -5 เมตร
  Then ระบบปฏิเสธและแสดงข้อความ "จำนวนต้องมากกว่า 0"
  And สต็อกคงเหลือ 5 เมตร (ไม่เปลี่ยนแปลง)
```

### AC ของ US-02

```gherkin
Scenario: จ่ายสินค้าจนสต็อกต่ำกว่า threshold
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 20 เมตร และ threshold = 15
  When พนักงานบันทึกจ่ายออก 8 เมตร
  Then สต็อกคงเหลือ 12 เมตร
  And ระบบส่งการแจ้งเตือนถึงผู้จัดการว่าสต็อกต่ำ

Scenario: จ่ายสินค้าโดยสต็อกยังสูงกว่า threshold
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 50 เมตร และ threshold = 15
  When พนักงานบันทึกจ่ายออก 10 เมตร
  Then สต็อกคงเหลือ 40 เมตร
  And ระบบไม่ส่งการแจ้งเตือน

Scenario: สต็อกเท่ากับ threshold พอดี
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 20 เมตร และ threshold = 15
  When พนักงานบันทึกจ่ายออก 5 เมตร
  Then สต็อกคงเหลือ 15 เมตร
  And ระบบไม่ส่งการแจ้งเตือน (เท่ากับ threshold ไม่ถือว่าต่ำกว่า)

Scenario: สต็อกต่ำกว่า threshold อยู่แล้วก่อนจ่าย
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 10 เมตร และ threshold = 15
  When พนักงานบันทึกจ่ายออก 3 เมตร
  Then สต็อกคงเหลือ 7 เมตร
  And ระบบส่งการแจ้งเตือนถึงผู้จัดการว่าสต็อกต่ำ
```

### AC ของ US-03

```gherkin
Scenario: คำนวณมูลค่าสต็อกแยกตามหมวดหมู่
  Given มีสินค้าในหมวด Electrical: "สายไฟ 2.5 sq.mm" สต็อก 100 เมตร ราคา 50 บาท/เมตร
  And มีสินค้าในหมวด Tools: "คีมตัด" สต็อก 10 อัน ราคา 300 บาท/อัน
  When ผู้จัดการเรียกดูรายงานมูลค่าสต็อก
  Then ระบบแสดง Electrical = 5,000 บาท
  And ระบบแสดง Tools = 3,000 บาท
  And ระบบแสดงมูลค่ารวมทั้งหมด = 8,000 บาท

Scenario: หมวดหมู่ไม่มีสินค้า
  Given ไม่มีสินค้าในหมวด Safety
  When ผู้จัดการเรียกดูรายงานมูลค่าสต็อก
  Then หมวด Safety ไม่ปรากฏในรายงาน (แสดงเฉพาะหมวดที่มีสินค้า)
```

### AC ของ US-04

```gherkin
Scenario: ตั้งค่า threshold ของสินค้า
  Given สินค้า "สายไฟ 2.5 sq.mm" มี threshold = 15
  When ผู้จัดการเปลี่ยน threshold เป็น 20
  Then threshold ของสินค้าต้องเป็น 20
  And การตรวจสอบสต็อกครั้งต่อไปต้องใช้ threshold = 20

Scenario: ตั้ง threshold เป็นค่าลบ
  Given สินค้า "สายไฟ 2.5 sq.mm" มี threshold = 15
  When ผู้จัดการเปลี่ยน threshold เป็น -5
  Then ระบบปฏิเสธและแสดงข้อความ "threshold ต้องไม่ต่ำกว่า 0"
  And threshold ยังคงเป็น 15
```

### AC ของ US-05

```gherkin
Scenario: เลือกช่องทาง Email
  Given ผู้จัดการตั้งช่องทางการแจ้งเตือนเป็น Email
  When สินค้าใดมีสต็อกต่ำกว่า threshold หลังจ่าย
  Then ระบบแจ้งเตือนผ่าน Email (print "[EMAIL] ...")

Scenario: เลือกช่องทาง SMS
  Given ผู้จัดการตั้งช่องทางการแจ้งเตือนเป็น SMS
  When สินค้าใดมีสต็อกต่ำกว่า threshold หลังจ่าย
  Then ระบบแจ้งเตือนผ่าน SMS (print "[SMS] ...")

Scenario: เลือกหลายช่องทางพร้อมกัน
  Given ผู้จัดการตั้งช่องทางการแจ้งเตือนเป็นทั้ง Email และ SMS
  When สินค้าใดมีสต็อกต่ำกว่า threshold หลังจ่าย
  Then ระบบแจ้งเตือนผ่านทั้ง Email และ SMS
```

## 4. In Scope / Out of Scope
**In Scope:**
- บันทึกรับ/จ่ายสินค้า + อัปเดตสต็อกใน memory
- ตรวจสอบสต็อกก่อนจ่าย ปฏิเสธถ้าไม่พอ
- แจ้งเตือน email/sms เมื่อสต็อกต่ำกว่า threshold (ใช้ print แทนส่งจริง)
- รายงานมูลค่าสต็อกรวมแยกตามหมวดหมู่
- ตั้งค่า threshold รายสินค้า
- เลือกช่องทางแจ้งเตือนได้ (Email / SMS / ทั้งสอง)

**Out of Scope:**
- ส่ง email/sms จริง (ใช้ print จำลอง)
- ระบบ login / authentication / authorization
- ฐานข้อมูลถาวร (persistent storage) — ใช้ in-memory เท่านั้น
- GUI หรือ Web interface
- การจัดการผู้ใช้หลายคนพร้อมกัน (concurrency)

## 5. Functional Requirements (FR)
| รหัส | ความต้องการ | จาก Story |
|------|-------------|-----------|
| FR-01 | ระบบต้องอัปเดตสต็อกทันทีหลังบันทึกรับ/จ่าย | US-01 |
| FR-02 | ระบบต้องตรวจสต็อกก่อนจ่าย และปฏิเสธถ้าสต็อกไม่เพียงพอ | US-01 |
| FR-03 | ระบบต้องแจ้งเตือนเมื่อสต็อกหลังจ่าย**ต่ำกว่า** threshold (strictly less than) ไม่แจ้งเมื่อเท่ากับ | US-02 |
| FR-04 | ระบบต้องคำนวณมูลค่าสต็อก (จำนวน × ราคาต่อหน่วย) แยกตามหมวดหมู่ พร้อมแสดงยอดรวม | US-03 |
| FR-05 | ระบบต้องให้ผู้จัดการตั้งค่า threshold รายสินค้าได้ โดย threshold ต้อง ≥ 0 | US-04 |
| FR-06 | ระบบต้องรองรับหลายช่องทางแจ้งเตือนพร้อมกัน (Email, SMS) | US-05 |

## 6. Non-Functional Requirements (NFR)
| รหัส | มิติ | ความต้องการ (วัดได้) |
|------|------|----------------------|
| NFR-01 | Performance | รายงานมูลค่าสต็อก 1,000 รายการ เสร็จภายใน 1 วินาที |
| NFR-02 | Maintainability | เพิ่มช่องทางแจ้งเตือนใหม่ได้โดยไม่แก้ business logic เดิม (OCP) |
| NFR-03 | Reliability | ถ้าช่องทางแจ้งเตือนใดส่งไม่สำเร็จ ช่องทางอื่นต้องยังทำงานได้ และสต็อกต้องอัปเดตถูกต้อง |

## 7. Design Notes
- การแจ้งเตือนต้องแยกออกจาก business logic ของสต็อก (SRP)
- คาดว่าจะมีหลายช่องทางแจ้งเตือน ควรออกแบบให้เพิ่มได้ง่ายโดยไม่แก้ service (OCP)
- ใช้ Dependency Injection — service ไม่ควรสร้าง notifier เอง (DIP)
- "ต่ำกว่า threshold" หมายถึง strictly less than (`<`) เท่านั้น ไม่รวม equal
